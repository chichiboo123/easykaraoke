# 여기 있어 노래방 · Easy Karaoke

> **세상의 모든 음악, 노래방 반주 영상 뚝딱**

**반주와 가사만 있으면, 노래를 들으며 가사 한 줄마다 스페이스바를 한 번씩.** 그것만 하면 노래방 영상이 만들어지는 브라우저 편집기입니다. 음원·가사·배경·글꼴·프로젝트와 렌더 결과는 서버로 전송되지 않습니다.

초등학생도 혼자 만들 수 있는 것을 목표로 합니다.

## V2에서 달라진 것

V1은 **음절 하나하나**에 타이밍을 찍는 방식이었습니다. 4분짜리 곡이면 스페이스바를 300~500번 정확히 눌러야 했고, 한 번 밀리면 그 뒤가 전부 어긋났습니다.

V2는 **가사 한 줄(블록)** 단위로 찍습니다. 한 곡에 20~40번이면 끝나고, 음절 타이밍은 줄 구간 안에서 글자 수와 받침을 고려해 자동으로 분배됩니다.

| | V1 | V2 |
|---|---|---|
| 타이밍 입력 단위 | 음절 | **줄(블록)** |
| 4분 곡 기준 Space 횟수 | 300~500회 | **20~40회** |
| 실수했을 때 | 그 뒤가 전부 밀림 | **그 줄만 다시 찍기** |
| 단계 | 5단계 | **3단계** |
| 가사 오타 수정 | 그 줄 타이밍이 사라짐 | **타이밍 유지** |

그 밖에 이번 판에서 고친 것:

- **음절이 음 길이만큼 차오릅니다.** V1은 보정 조건이 실제로는 한 번도 실행되지 않아 모든 음절이 0.35초 만에 차오르고 멈췄습니다.
- **하이라이트가 글자와 정확히 겹칩니다.** V1은 음절 분리가 공백을 버리는데 렌더러는 공백 포함 원문을 그려서, 띄어쓰기 개수만큼 채우기가 왼쪽으로 밀렸습니다.
- **내보내기를 여러 번 해도 소리가 살아 있습니다.** V1은 한 번 내보내면 그 뒤로 미리보기까지 무음이 됐습니다.
- **타이밍 밀기(전역 오프셋)와 0.5×·0.75× 느린 재생**으로 반응 지연과 블루투스 출력 지연을 보정합니다.
- **파형·블록·재생헤드가 한 화면에** 있고, 타임라인을 누르면 그 자리로 이동하며 블록 끝을 끌면 길이가 바뀝니다.
- **되돌리기(Ctrl+Z)가 화면에 버튼으로** 있습니다.
- **드래그&드롭이 실제로 동작합니다.** V1은 "놓아주세요"라고 써 놓고 핸들러가 없어, 놓으면 페이지를 떠나 작업이 날아갔습니다.
- **15초만 시험 렌더**로 4분을 기다리지 않고 결과를 확인할 수 있고, 타이밍이 일부만 있어도 내보낼 수 있습니다.
- **시작 전 카운트다운**이 기본으로 들어갑니다.
- **어두운 편집 화면이 기본**입니다(밝은 화면으로 전환 가능). 결과물이 어두우므로 도구도 어두워야 색을 판단할 수 있습니다.
- 긴 가사 자동 줄바꿈, 배역 배지 자동 폭, 배경 이미지 종횡비 유지.

자세한 배경은 [docs/UX_ANALYSIS.md](docs/UX_ANALYSIS.md)와 [docs/V2_PLAN.md](docs/V2_PLAN.md)를 참고하세요.

## 만드는 순서

1. **준비** — 반주 파일을 끌어다 놓고, 가사를 한 줄에 한 소절씩 붙여넣습니다. 뮤지컬 모드를 켜면 `[배역] 가사` 형식으로 배역도 함께 만들어집니다.
2. **타이밍** — 재생하고, 가사 줄이 시작될 때마다 <kbd>Space</kbd>. 틀리면 그 줄의 `다시 찍기`만 누르면 됩니다.
3. **꾸미기·저장** — 무대·글자·배경을 고르고 MP4로 내려받습니다. 작업 파일(.mkaraoke)로도 저장할 수 있어요.

### 타이밍 화면에서 더 할 수 있는 것

- **글자 단위 편집** — 토글을 켜면 글자마다 <kbd>Space</kbd>를 눌러 찍습니다. 색이 차는 기준은 여전히 **한 줄**이고, 그 줄 안에서 글자마다 속도가 정해집니다.
  - 처음부터 글자 단위로 찍어도 되고, 줄 단위로 찍어 둔 곡을 다듬어도 됩니다.
  - 한 줄의 마지막 글자 다음 <kbd>Space</kbd>는 **그 줄을 닫고 다음 줄을 바로 시작**합니다. 줄을 일일이 고를 필요가 없습니다.
  - 다시 찍지 않고 속도만 손보려면 글자를 고른 뒤 `−10` / `+10` 버튼을 쓰세요. 줄 구간은 그대로 유지됩니다.
- **간주 넣기** — 가사가 없는 구간을 `♪ 간주중 ♪`으로 채웁니다.
- **줄 추가·이동·삭제** — 가사 블록 목록에서 바로 할 수 있습니다.
- **타임라인 보기** — 확대·축소, 전체 보기, 좌우 스크롤. 휠로 이동하고 <kbd>Ctrl</kbd>+휠로 확대, <kbd>Shift</kbd>+드래그로 끌어서 이동합니다.

### 단축키

| 키 | 하는 일 |
|---|---|
| <kbd>Space</kbd> | 줄 찍기 · 글자 단위 편집에서는 글자 경계 맞추기 (멈춰 있으면 재생 시작) |
| <kbd>K</kbd> | 재생 / 정지 |
| <kbd>←</kbd> <kbd>→</kbd> | 2초 이동 |
| <kbd>Shift</kbd> + <kbd>←</kbd> <kbd>→</kbd> | 고른 블록 50ms 밀기 |
| <kbd>Alt</kbd> + <kbd>←</kbd> <kbd>→</kbd> | 고른 블록 10ms 밀기 |
| <kbd>Ctrl</kbd>/<kbd>⌘</kbd> + <kbd>Z</kbd> | 되돌리기 |
| <kbd>Ctrl</kbd>/<kbd>⌘</kbd> + <kbd>Shift</kbd> + <kbd>Z</kbd> | 다시 실행 |
| <kbd>Ctrl</kbd>/<kbd>⌘</kbd> + <kbd>S</kbd> | 작업 파일(.mkaraoke) 저장 |

## 설치와 실행

Node.js 22 이상을 권장합니다. 런타임 의존성이 없어 별도 패키지 다운로드가 필요 없습니다.

```bash
npm install
npm run build
npm run dev
```

`http://localhost:5173`에서 확인합니다.

| 명령 | 하는 일 |
|---|---|
| `npm run typecheck` | 타입 검사 |
| `npm test` | 단위 테스트 (가사 분리·타이밍 계산 등 순수 로직) |
| `npm run test:e2e` | 브라우저 스모크 테스트 (실제 제작 흐름을 Chromium으로 실행) |
| `npm run test:all` | 위 둘 다 |
| `npm run build` | 빌드 + 저장소 루트 동기화 |
| `npm run check:deploy` | 배포 산출물 검사 |

브라우저 테스트는 외부 CDN을 느리게 만든 상태로 돌아갑니다. 네트워크에 흔들리지 않으면서,
학교 방화벽처럼 CDN이 느린 환경에서도 앱이 제대로 뜨는지 함께 검사합니다.
로컬에 Chromium이 이미 있다면 `PLAYWRIGHT_CHROMIUM_PATH`로 경로를 지정할 수 있습니다.

**빌드 산출물을 함께 커밋해야 합니다.** 이 저장소는 GitHub Pages의 "Deploy from a branch /(root)" 설정을
지원하려고 컴파일 결과를 루트에도 둡니다. `src/`를 고쳤다면 `npm run build` 후 변경된 파일을 함께 커밋하세요.
CI가 이 불일치를 잡습니다.

## GitHub Pages 배포

이 앱은 백엔드가 없는 정적 웹앱이므로 Cloudflare Pages가 반드시 필요하지 않습니다. 저장소의 `.github/workflows/deploy-pages.yml`이 `work` 또는 `main` 브랜치 push 시 테스트와 빌드를 수행하고 `dist` 폴더를 GitHub Pages에 배포합니다.

권장 방식은 저장소의 **Settings → Pages → Build and deployment → Source**에서 **GitHub Actions**를 선택하는 것입니다. 이후 Actions 탭의 **Deploy to GitHub Pages** workflow를 수동 실행하거나 대상 브랜치에 push하면 됩니다. 프로젝트 사이트가 `https://사용자명.github.io/저장소명/`처럼 하위 경로에 배포되어도 동작하도록 모든 정적 자산과 JavaScript import는 상대 경로를 사용합니다.

현재 저장소는 **Deploy from a branch → /(root)** 설정도 지원합니다. `npm run build`가 `app.js`, `types.js`, `lib/`, `styles.css`, `fonts/`를 저장소 루트에도 동기화하며 해당 결과를 커밋합니다. 따라서 기존 Pages 설정을 바꾸지 않아도 최신 커밋을 배포하면 동작합니다. 다만 테스트를 통과한 결과만 배포하는 GitHub Actions 방식을 권장합니다.

배포 전에는 아래 명령으로 HTML, JavaScript 모듈과 CSS가 모두 출력 폴더에 존재하는지 검사할 수 있습니다.

```bash
npm run build
npm run check:deploy
```

화면이 비어 있다면 GitHub의 **Actions → Deploy to GitHub Pages** 또는 Pages에 지정한 배포 브랜치가 최신 커밋인지 확인한 뒤 브라우저에서 강력 새로고침하세요. 루트의 `app.js`와 `styles.css`가 404라면 아직 이 수정 커밋이 Pages에 반영되지 않은 상태입니다.

## 권장 브라우저와 제한

최신 데스크톱 Chrome/Edge처럼 `canvas.captureStream`, `MediaRecorder` 및 `video/mp4`(H.264/AAC)를 함께 제공하는 환경을 권장합니다. 브라우저가 MP4 MediaRecorder를 제공하지 않으면 내보내기 버튼을 활성화하지 않으며 최신 호환 브라우저 사용을 안내합니다. 출력은 메모리에 모든 프레임을 쌓지 않고 실시간으로 녹화하므로 곡 길이만큼 시간이 걸립니다. 정밀 편집은 PC를 권장합니다.

## 폰트

| 글꼴 | 출처 |
|---|---|
| **TJ 노래하는즐거움체 M** (기본) | 저장소 포함 — `public/fonts/TJJoyofsingingM.otf`, 원본 그대로(변환·subset 없음) |
| 주아체 · 도현체 · 검은고딕 · 고운돋움 · 노토 산스 | Google Fonts CDN (OFL-1.1) |

구글 글꼴은 한글을 unicode-range 조각으로 나눠 주므로 실제로 쓰는 글자만 내려옵니다.
CDN에 닿지 못하면 해당 카드가 `못 불러옴` 배지와 함께 비활성 처리되고, TJ 글꼴과 기본 글꼴로 계속 만들 수 있습니다.
글꼴 스타일시트는 비차단으로 불러오므로 CDN이 느려도 앱은 즉시 뜹니다.

**공개 배포 전 확인**: GitHub Pages 배포는 저장소에 포함된 TJ 글꼴 파일의 재배포에 해당합니다.
TJ미디어의 현재 재배포 조건을 반드시 확인하세요. 자세한 내용은 [FONT_LICENSE_NOTES.md](FONT_LICENSE_NOTES.md).

## 기술

TypeScript, Canvas 2D, Web Audio API, MediaRecorder, IndexedDB, FontFace, Intl.Segmenter를 사용합니다. 번들러도 런타임 의존성도 없습니다. 백엔드, 분석 SDK, 광고, AI API가 없습니다. 다만 글꼴(Pretendard)과 아이콘(Material Icons)은 CDN에서 불러오며, 이 두 가지를 불러오지 못해도 앱은 그대로 동작합니다(아이콘 자리에 글자 라벨이 나옵니다). 선택 근거와 조사 대상은 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)에 기록했습니다.

## V2 범위

AI 자동 싱크, 가사 추출, 보컬 분리, 점수, 로그인, 클라우드 저장, 협업은 포함하지 않습니다. 음절 단위 수동 미세 조정도 아직 없습니다(블록 단위 조정과 전역 오프셋으로 충분하도록 설계했습니다). 공개 또는 상업 배포 전에 특히 TJ 폰트 재배포 조건과 모든 포함 글꼴 파일의 라이선스를 다시 확인해야 합니다.
